# 虚构小型灌水展台：试水压力 + 畦节奏 + 阀组组织

纯合成教学模型，与任何真实灌溉/管网标准无关。Python 3.11，仅用标准库。

## 领域对象（全部来自题面的“旧巡检 + 接头表”口径）

* **干管树**：接头表把实物端点连成一棵有根树。每段有压降系数 `k`（首端整数
  压头 `H`，整数喷口流量）。
* **具名水嘴（具名实体）**：水嘴是旧巡检命中的具名实体。不同断链段里标签相同
  的两个水嘴**不能相连**——树的边只允许在接头表登记的实物端点之间形成，重名
  水嘴永远解析成两个不同节点，绝不就近合并。
* **本批核定范围**：按报告当时的实际覆盖，核定本批检查过的水嘴和干管段。
  **跨未检段的支路不给出水许可**：未检段下游的任何喷口子集一律试水失败，
  无论压头算出来是多少。
* **压降**：每段压降 = 系数 × 该段流过的总流量，从首端沿途相减。
  压力与流量都是整数，因此所有余压也是整数。

## 试水（按“同时开的一组喷口”独立出证）

`pressure_test(tree, open_nozzles)` 对**同一组同时打开的喷口**一次性计算：

1. 若有喷口位于未检段下游 → 整组拒批（`permitted=False`），不出压力。
2. 自底向上汇总每条边的子树总流量，自根向下沿途减压降。
3. 逐嘴给出余压，并与该嘴最低压力比较。

**不能把分别单开的成功证相加。** 单口子集达标只证明该子集；并开组必须用并开
组自身的总流量重新试。教学网（首压 3、干管系数 1、两支系数 0、每嘴流量 1、
下限 2）：

| 试水组 | 公共段流量 | A、B 余压 | 判定 |
|--------|-----------|-----------|------|
| 只开 A | 1 | A=2 | 达标 |
| 只开 B | 1 | B=2 | 达标 |
| A、B 同开 | 2 | A=1、B=1 | **双双不达标** |

仅把实测首压改成 2，则单口余压也只剩 1（2 − 1×1），单开证同时作废。

## 畦节奏（受水单）

* 一畦可挂一个或几个喷口；每个开口每个时格只浇一畦，每畦每格至多一口。
* 每畦有：允许时格窗口、应浇格数 `need`、相邻两次受水之间必须空出的格数
  `gap`（两次受水时格之差必须 `> gap`）。
* **换班不重置间歇**：换班时真实已浇的一格仍算在间歇里。时格全局连续编号，
  上一班末尾记为 0 或负数，跨班约束与班内同式检查。
* `enumerate_schedules` 做全量枚举（最多八嘴、八格，组合很小），逐条核对窗口、
  容量、需量与间歇，并把“有水却排不下”的情形显式判为不可行而不是放行。

教学例（两畦各只认自己的嘴、各需一格、前两格都可浇、gap=0）可行方案里含
`格1浇A、格2浇B`（先 A 后 B 可办）；若两畦窗口都只剩第 1 格，则格 1 必须
A、B 同嘴组并开，试水余压 1 < 2，**没有可交场的阀位+受水单**。

## 两种阀门组织（园丁只交所选的一套）

### 方式一：泵房总阀台（同格总阀）

泵房收齐同一格的全部点名请求后，签真实阀组，核共管余压后一次开闭。每次换
阀组占一个**调阀拍**，该拍无一畦记作浇过。教学例默认调阀拍为零（每格自由
重配，不耗拍）。

### 方式二：开工前锁定每根出支流量上限（发阀牌给支房小阀）

* 支房不必等总阀拍；前提是各支房**按各自已领许可同时开**，也不会让公管上
  任何一嘴亏压。安全条件直接用并开试水核验，不靠单开口证拼接。
* 限额可以整支保留，也可划给多个安全的并开组（同一时刻活在支房手里的许可
  之并，必须本身是试水达标组）。
* **同一支房在两班交接后不能复用已收走的阀牌**：阀牌有生命周期，`issue` →
  `collect` 后即终结；再要开度必须重新 `issue` 新牌。
* 实浇历史必须从出水回条续上：`DosingLedger` 只接受真实试水达标的组产生的
  回条，跨班间歇从回条上的时格连续计算。

## 两支两班场景（首压 3、公共段系数 1、下限 2，两班各一只独立阀）

* 把“单开达标”分别发给两个支：各自单开余压 2 达标，但两支并开公共段流量 2、
  余压跌成 1 → 这种发牌方式不满足方式二的安全前提。
* 守一嘴的可行办法：**收回其中一支的阀牌**，使全场活许可总流量 ≤ 1。
* 若改由总阀掌握两畦请求、允许一格调阀、且两畦窗口都够宽，则可交替实浇
  （例：格 1 浇 A → 调阀拍 → 格 3 浇 B，只耗 1 拍）。
* 再缩短其中一个窗口（例如 B 只剩格 2 可浇）：交替顺序被窗口顶死，1 拍预算
  不再够用，必须追加调阀拍或放弃一畦——缩短窗口的代价由枚举直接给出。
