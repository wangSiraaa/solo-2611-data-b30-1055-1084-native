# 组织变更后的层级预算分解、支出占额与虚构工坊成本联算

纯 Python 3.11 + 标准库（`sqlite3`、`fractions`）实现，无第三方依赖。服务物理
分离、仅通过**已发布的不可变组织产品版本**或**冻结报价快照**衔接，解决两类
问题：部门迁移后旧预算与已承诺支出在新旧上级同时占额；互供服务中心成环时
如何把实付成本精确归到生产线、识别困在闭圈里无法归线的钱，并据此签外协订单。
预算金额均为整数分；成本联算与单件负担全程使用 `Fraction` 精确分数。

## 目录结构

```
orgbudget/
  errors.py          领域异常（组织/预算/成本联算/实付账/联营会/订单各自成体系）
  budget.py          纯函数分解：按权重大数余数法（下取整 + 余数降序 + ID 并列）
  org_service.py     组织编制服务：唯一根父子树、子树移动、叶停用、不可变版本快照
  budget_service.py  预算执行仓：根预算、权重分解、承诺、实际支出、换版与覆盖校验
  costflow.py        成本联算纯函数：SCC 缩 DAG + Fraction 高斯消元、逐来源归线、困圈
  ledger.py          实付账：预算树子树就近归集一次、取消只留实付、分送表版本链
  association.py     联营会：集中流向、逐来源归线报价、撤回失效、跨中心闭圈、离线复核
  boundary.py        工坊边界表：同址中心合并对外、入口单位去向、跨工坊封闭圈
  order.py           订单纯函数：自制/外协枚举最低成本、封价、阻止降价约束识别
  order_desk.py      订单员服务：本期外协名册与名额占用、撤资格留痕、事务化签单
  audit.py           独立重算审计（Fraction 独立实现 + 直接读原始事件表核对）
demo/
  scenarios.py           六个预算端到端案例，可直接复跑
  workshop_scenarios.py  十个成本联算/归线/签单端到端案例
tests/                   unittest 用例（含跨进程争用、1000+300 组随机网络守恒核对）
```

## 核心规则与实现落点

### 组织编制服务（`OrgService`，独立 SQLite 库）

- 唯一 `department_id`、唯一根、父子树；建部门 / 移动完整子树 / 停用叶部门。
- 移动只改被移动节点一条父边：天然是整棵子树移动，不存在“部分移动”；
  根不可移动，挂到自身或子孙下报 `CycleError`，发布时 `OrgProduct` 构造器
  再做单根 / 无环 / 唯一父项全量校验。
- 每次 `publish()` 把全量快照写入 `org_dept`，版本号严格递增；
  **已发布产品不可变**，后续移动只产生新版本，旧版本行永不更新。
- 组织维护独立于预算，行政客户可直接用祖先 / 后代 / 子树查询。

### 预算执行仓（`BudgetService`，另一个独立 SQLite 库）

- 每个方案在 `scheme` 表明确绑定一个组织产品版本；预算端查询时按方案绑定
  的版本实时向组织服务读取**本次产品**，不缓存旧树，迁移部门不可能出现
  两份额度。
- 分解（`budget.allocate_children`）：按权重比例下取整，丢掉的分按小数余数
  降序补，余数并列按部门 ID 升序；恒有 `Σ孩子预算 = 父预算`。
- 叶可用额 = 分配预算 − 实际支出 − 未结承诺剩余，开立承诺时在事务内校验，
  不得为负；支出仅追加，不得超过承诺剩余；取消只释放剩余，已支出不可撤销。
- 承诺 `request_no` 是全局唯一幂等键，支出事件有独立幂等键，丢响应重试
  不二次占额；同键不同内容报 `IdempotencyConflict`。
- 换版 `revise_budget()`：预算人员为**新产品**的每条直接父子边补齐正权重
  （缺边 / 多边均拒绝），自根向下重算全部预算，再用全部历史承诺 / 支出
  事件做覆盖校验。任一叶覆盖不了“实际支出 + 未结承诺剩余”则整次换版
  回滚并在 `rejected_revision` 留痕；**承诺的部门身份永不改写**。
- 拒绝不影响组织服务已发布的新产品，预算仓继续绑定旧版。
- 汇总沿方案绑定产品的树闭包计算；旧方案查询永远沿旧树，不按当前树解释历史。

### 并发与持久化

- 所有写操作在单连接 `BEGIN IMMEDIATE` 事务内完成“读取校验 → 写入”，
  SQLite 写锁把并发提交串行化；测试覆盖线程与**独立进程**两种争用，
  两个连接争同一剩余额时最多一方成功。
- 全部状态落 SQLite 文件，服务重启后事实完整可读。

### 独立审计（`audit.audit_scheme`）

刻意不调用生产代码的分解 / 汇总路径：

1. 直接 SQL 读组织快照、承诺与仅追加支出事件；
2. 用 `fractions.Fraction` 重新推导分解，与落库分配逐部门比对；
3. 从原始事件重建每叶实际支出与未结占额，逐级核对守恒、覆盖、可用额非负、
   祖先汇总 = 后代叶事实之和。2000 组随机参数下两套实现结果完全一致；
   直接篡改分配或事件表会被审计抛出 `InvalidTree`。

## 成本联算（`costflow.py` 纯函数 + `ledger.py` 实付账）

### 网络与精确分数求解

- 节点分**服务中心**（可注直接成本，各签一张分送表，比例合计严格 100%，
  目标可送另一中心或某生产线）与**生产线**（只进不出）。
- “已受入的内部服务按同一比例再分”给出吞吐量方程
  `q_i = d_i + Σ_{j→i} q_j·share(j,i)`；线金额
  `t_L = Σ_{j→L} q_j·share(j,L)`。
- 中心间允许成环：先用 Tarjan 求强连通分量（SCC）把网络缩成 DAG，源向逐个
  分量求解；多节点 SCC 建稠密线性方程组做 Fraction 高斯-约当消元，
  自环计入对角元、跨 SCC 入流可指向分量内任意节点。全程无浮点。
- **闭圈语义**：无钱流入的纯内部空圈按“从零开始的实际传递”吞吐量为 0，
  不污染任何线、不产生困钱报告；闭 SCC 内（含外部注入后被吸入的钱）若有
  正成本，方程无解，按**来源**报告困圈金额与所在分量，明确这笔钱无法归线。
- 结果内置两道守恒断言：开中心 `q = 直接成本 + 受入`；全局
  `直接成本 = 各线金额 + 困圈金额`。逐来源 `SourceTrace` 给出每条中心边上
  该来源的承载量，买方可逐跳复核“每一项直接来源怎样走进最终数”。

### 实付账（`LedgerService`，独立 SQLite 库）

- 每个中心对应预算采用版中的一棵子树；支付在入账叶上沿预算树向上找
  **最近的登记中心**归集一次，中心自身或其子树内的支付都进该中心。
- 支付可部分实付；取消只撤销未付余款，已支付部分永久保留，联算只认真实
  支付额。支付号是幂等键，同号不同内容报 `PaymentConflict`。
- 分送表按中心版本化，重报须带 `expected_version`，旧版快照留痕。
- 账通过 `bind_budget_version` 绑定预算仓生效方案的组织产品版本；分部迁移
  但预算换版被拒绝时，预算仓仍绑旧树，本账因此**接的仍是预算所用树**。

### 题面数字回归（`tests/test_costflow.py`、`demo/workshop_scenarios.py`）

X、Y 各实付 6，X 半送 Y 半送 M、Y 半送 X 半送 N：吞吐量 X=Y=12，最终
M=N=6；只给 X 增实付 3 后 M=8、N=7。

## 联营会、归线报价与订单签单

### 联营会（`association.py`，独立 SQLite 库）

- 集中接收各中心完整分送表后跑联算，签发**逐来源归线报价** `Quote`，
  签发即冻结线金额、逐来源归线、每条承载边与分送表版本。
- 某中心撤回一条服务量时，所有来源走向经过该中心出边的**在用报价**
  （含已承兑的）精确置 `INVALIDATED` 并留痕；订单员签新单前 `require_live`
  拦截失效报价。一方离线时仍可凭冻结快照复核已承兑旧报价，不实时呼叫中心。
- `cross_center_loops` 对当前网络跑 SCC，报出全部跨中心封闭圈。

### 工坊边界表（`boundary.py`）

- 若干同址中心作为一个工坊，只对外给出每个**外来入口**进一单位时在各出口
  流出、滞在内部闭圈、进入各线或滞在跨工坊闭圈的准确比例，以及自有成本的
  同口径证明；工坊内部互供边不出现在边界表里，不要求外协掌握内部明细。
- `combine_and_find_closed_loops` 组合多张边界表（可附原始分送表补全零流量
  闭圈边），在工坊级缩图上发现跨工坊封闭圈。

### 订单员（`order.py` 纯函数 + `order_desk.py` 签单服务）

- 单件负担 = 线本期签出金额 ÷ 正数标准产量；某品种只要自制至少一件就发生
  一次该品种开线费；现场自制总件数受单一共同上限约束。
- 对自制向量完全枚举，每个向量用分层状态扩展 DP 求外协最低分配，得全局
  最低成本与确定性（字典序）最优方案；`blockings` 逐类放松一档反算，严格
  降本的才是真实阻止项，直接回答“哪条真实开线或外协额度阻止降价”。
- 必须交足且最低成本不超买方封价才可签：不可行报 `InfeasibleOrder`，
  超封价报 `SealPriceRejected`，均不占名额。
- 每家外协每个期间一个共同名额；`sign` 在 `BEGIN IMMEDIATE` 事务内完成
  “报价校验 → 求解 → 封价 → 占名额”，同时签出的两单不可能许给同一班
  （`SupplierCapacityTaken`）。撤资格只影响之后的新单，历史订单原样保留。

题面订单回归：2 件 M、1 件 N，本地最多 2 件、外协班合计 1 件，M 报价 7、
N 报价 9、M 开线费 2、N 开线 0 → 自制一 M 一 N + 外协一 M，最低 21，封价
22 内签出；X 增 3 后最低 24 拒签；旧成本撤外协 M 资格后最低 23 拒签。

## 独立审计（`audit.audit_costflow`）

刻意不调用生产代码的 SCC/消元路径：直接 SQL 读支付、中心与分送表，用
Kosaraju 两遍 DFS 独立识别 SCC，对开网络建稠密方程组做独立 Fraction 消元，
核对分送表合计 1、就近归集一次且取消余款不计、吞吐量方程、全局守恒
（注入 = 归线 + 困圈），并与生产 `solve_allocation` 结果逐项比对。
`tests/test_costflow_fuzz.py` 在 1000 张含自环/多 SCC/闭圈的随机网络上
核对守恒与逐来源份额，另对 300 张“全部中心可达生产线”的网络断言无困圈。

## 演示案例（`python -m demo.scenarios`）

1. 三层树余分分配（含余数并列按 ID、不同余数两种情形，并与 Fraction 实现交叉核对）；
2. 带未结承诺的部门子树迁移、换版重算、身份不改、旧版沿旧树冻结；
3. 新预算不足被整次拒绝，组织新产品照发，预算仓继续绑旧版；
4. 支出后部分取消：已支出保留、剩余占额释放、取消后禁止再支出；
5. 并发承诺争额度最多一方成功、同请求重试不二次占额（线程级）；
6. 20 部门 / 深度 5 / 100 笔支出的大规模场景，迁移前后各做一次独立审计。

`python -m demo.workshop_scenarios` 另演示十个成本联算场景：X/Y 互供归线、
21/24/23 三次签单决策、两单争外协名额、孤立空圈与困圈指认、撤回失效、
迁移拒绝沿旧树、工坊边界表与跨工坊封闭圈、独立审计。

范围限定：不做员工工资、现实预算制度或审批界面；成本联算规模上限为
6 中心 / 4 品种 / 十来件订单，枚举与消元在该规模下本地即可完成。
