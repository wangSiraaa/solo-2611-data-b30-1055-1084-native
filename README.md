# 组织变更后的层级预算分解与支出占额 + 设备会计

纯 Python 3.11 + 标准库（`sqlite3`）实现，无第三方依赖。各服务物理分离、
仅通过公开查询与**已发布的不可变组织产品版本**衔接，解决部门迁移后旧预算
与已承诺支出在新旧上级同时占额的问题；设备会计在其上管理购建底单、原值
封存、折旧换件与报废限额。所有金额均为整数分。

## 目录结构

```
orgbudget/
  errors.py            领域异常（组织 / 预算 / 设备各自成体系）
  budget.py            纯函数分解：按权重大数余数法（下取整 + 余数降序 + ID 并列）
  org_service.py       组织编制服务：唯一根父子树、子树移动、叶停用、不可变版本快照
  budget_service.py    预算执行仓：根预算、权重分解、承诺、实际支出、换版与覆盖校验
  equipment.py         设备会计纯函数：安装费工时分摊、累计损耗、报废损失
  equipment_service.py 设备会计中心：购建底单、原值封存、机身登记、限额与独占拨付
  local_cabinet.py     离线柜：凭拨付单在本地核算拆装、交还余款回执
  audit.py             预算独立重算审计（Fraction 独立实现 + 直接读原始事件表核对）
  equipment_audit.py   设备账独立重算审计（分摊 / 封存 / 限额 / 部件状态机）
demo/
  scenarios.py           预算侧六个端到端案例，可直接复跑
  equipment_scenarios.py 设备会计端到端案例（题面故事线）
tests/               76 个 unittest 用例（含跨进程争用、2000 组模糊交叉核对）
```

python3 -m demo.scenarios                  # 预算侧演示，产物落在 demo_data/*.db

## 核心规则与实现落点

### 组织编制服务（`OrgService`，独立 SQLite 库）

- 唯一 `department_id`、唯一根、父子树；建部门 / 移动完整子树 / 停用叶部门。
- 移动只改被移动节点一条父边：天然是整棵子树移动，不存在“部分移动”；
  根不可移动，挂到自身或子孙下报 `CycleError`，发布时 `OrgProduct` 构造器
  再做单根 / 无环 / 唯一父项全量校验。
- 每次 `publish()` 把全量快照写入 `org_dept`，版本号严格递增；
  **已发布产品不可变**，后续移动只产生新版本，旧版本行永不更新。
- 组织维护独立于预算，行政客户可直接用祖先 / 后代 / 子树查询。

### 预算执行仓（`BudgetService`，另一个独立 SQLite 库）

- 每个方案在 `scheme` 表明确绑定一个组织产品版本；预算端查询时按方案绑定
  的版本实时向组织服务读取**本次产品**，不缓存旧树，迁移部门不可能出现
  两份额度。
- 分解（`budget.allocate_children`）：按权重比例下取整，丢掉的分按小数余数
  降序补，余数并列按部门 ID 升序；恒有 `Σ孩子预算 = 父预算`。
- 叶可用额 = 分配预算 − 实际支出 − 未结承诺剩余，开立承诺时在事务内校验，
  不得为负；支出仅追加，不得超过承诺剩余；取消只释放剩余，已支出不可撤销。
- 承诺 `request_no` 是全局唯一幂等键，支出事件有独立幂等键，丢响应重试
  不二次占额；同键不同内容报 `IdempotencyConflict`。
- 换版 `revise_budget()`：预算人员为**新产品**的每条直接父子边补齐正权重
  （缺边 / 多边均拒绝），自根向下重算全部预算，再用全部历史承诺 / 支出
  事件做覆盖校验。任一叶覆盖不了“实际支出 + 未结承诺剩余”则整次换版
  回滚并在 `rejected_revision` 留痕；**承诺的部门身份永不改写**。
- 拒绝不影响组织服务已发布的新产品，预算仓继续绑定旧版。
- 汇总沿方案绑定产品的树闭包计算；旧方案查询永远沿旧树，不按当前树解释历史。

### 设备会计中心（`EquipmentService`，第三个独立 SQLite 库）

- **购建底单**：每张底单认领预算仓一笔真实实付事件（及其所属承诺），一笔
  实付可拆给若干具名部件，也可作为共用安装费按受益部件工时比例分摊
  （与预算分解同一套大数余数法，同余数按部件号补分）。底单落账即快照
  所属叶与当前方案采用的组织产品版本，**后续迁编不改写早期入账归属**。
- **封存三条红线**：实付事件与承诺必须真实；一笔实付全库只领一次（重领
  拒封）；每张底单各来源之和等于实付原件（漏分 / 超分拒封）；实付所属叶
  须与设备归属叶一致（跨分部拿错拒封）。会计无需等工坊提出换件即可独立
  封存；底单在封存后变动则封存过期，须重新封存。退役件原值是历史事实，
  涉及它的底单不得再更正。
- **机身与折旧**：按实际投用期、归零期数与部件号登记机身；已用期数 =
  当前期间 − 投用期间，累计损耗 = 原值 × 已用期数 ÷ 总期数向下取整、
  最多到原值；在库备件不折旧。
- **限额与独占拨付**（现场拆装只实现这一种开拆方式）：每个工坊（叶）每期
  一次报废损失总限额；中心把其中一笔实际额度独占拨给某台离线柜并锁定
  受益设备——这笔钱在柜上交还前不得再给另一台设备，余款交还后才回到
  可用限额（可用 = 限额 − 已确认损失 − 在途拨付）。
- **离线柜**：领单时拉取受益设备快照，此后全程离线；据实际见到的旧件与
  残件先核算（逐件账面 − 残件，损失最低为零）再扣柜上留存；拆单严格按
  登记先后结算，前序未了结后续不能先动；残件记录可在结算前更正。
- **拆装交易**：只有整套旧件都在机上且限额够，才一次拆下已签那套、装上
  有自己购建底单的新件；新件单独计龄，未拆部件照原日龄走。中心导入回执
  时按自己的封存账逐件重算核对，不符整单拒绝；回执丢失可按退役件原号
  查到此次装了什么，已拆旧件不可能按猜重拆。

### 并发与持久化

- 所有写操作在单连接 `BEGIN IMMEDIATE` 事务内完成“读取校验 → 写入”，
  SQLite 写锁把并发提交串行化；测试覆盖线程与**独立进程**两种争用，
  两个连接争同一剩余额（预算承诺或限额拨付）时最多一方成功。
- 全部状态落 SQLite 文件，服务重启后事实完整可读。

### 独立审计（`audit.audit_scheme` 与 `equipment_audit.audit_equipment`）

刻意不调用生产代码的分解 / 汇总 / 分摊 / 结算路径：

1. 直接 SQL 读组织快照、承诺与仅追加支出事件、设备仓原始行；
2. 用 `fractions.Fraction` 重新推导预算分解与安装费分摊，逐部门 / 逐部件
   与落库值比对；
3. 从原始事件重建每叶实际支出与未结占额、每工坊每期已确认损失与在途
   拨付，核对守恒、覆盖、可用额非负、限额不被突破、部件状态机一致。
   2000 组随机参数下两套实现结果完全一致；直接篡改分配、事件、封存或
   交易表都会被审计抛出。

## 演示案例

`python3 -m demo.scenarios`（预算侧）：

1. 三层树余分分配（含余数并列按 ID、不同余数两种情形，并与 Fraction 实现交叉核对）；
2. 带未结承诺的部门子树迁移、换版重算、身份不改、旧版沿旧树冻结；
3. 新预算不足被整次拒绝，组织新产品照发，预算仓继续绑旧版；
4. 支出后部分取消：已支出保留、剩余占额释放、取消后禁止再支出；
5. 并发承诺争额度最多一方成功、同请求重试不二次占额（线程级）；
6. 20 部门 / 深度 5 / 100 笔支出的大规模场景，迁移前后各做一次独立审计。

`python3 -m demo.equipment_scenarios`（设备会计，题面故事线）：

1. 电机 8、机座 4、安装费 3 按工时 1:2 分摊 → 原值 9 和 6，逐分钱痕可查；
2. 旧库部分实付后取消余款（承诺 10 实付 7 取消 3），核原值仍看得到；
3. 限额 6 换电机：账面 6 − 残件 0 = 损失 6 恰好可办；回单丢失按原号查；
4. 更正工时为 2:1 重封同一组实付：电机变 10、账面 7，原工单被拒；
5. 另一项已办退役占去限额 1：账面 6 限额剩 5 须拒，机座照常计龄；
6. 独占拨付终例：在途 5 挤占则 B 没足 2；一柜独占 6 按 4 及 2 先后办完；
   残件记录改到实际损失超 6，谁都不能先动旧件；
7. 迁编不改写早期入账归属；设备账独立审计全部通过。
   规模：12 个部件、三个期间、两台本地柜。

范围限定：不做员工工资、现实预算制度或审批界面；现场拆装只实现独占拨付
一种开拆方式（单次拆装票未实现）。
